## 2026-07-29 - Rate Limiting Parameter Misalignment in Admin Auth Routes
**Vulnerability:** In `/admin/login` and `/admin/login/2fa`, misordered arguments in calls to the inline rate-limit helper `guardRate` merged the caller's IP into the `scope` string, mapped the static rate limit (e.g., 5 or 8) as the client `id`, mapped the rolling window duration (600 seconds) as the `max` limit, and omitted `windowSec`. Consequently, `windowSec` was resolved as `undefined`, preventing rolling window expiration resets (due to `now > NaN` evaluating to `false`) and raising the effective limit to 600 concurrent requests.
**Learning:** Argument signature mismatches on generic wrappers like `guardRate` can cause silent security failures (such as setting important security variables to `undefined` or swapping bounds parameters) if wrapper signatures diverge from underlying utility parameters without static type-system errors or explicit interface guarantees.
**Prevention:** Always enforce strict TypeScript function typing and write unit or static analysis tests confirming that parameter sequences mapped into wrappers align with target handlers. Define cohesive parameter objects (e.g. `{ c, scope, id, max, windowSec }`) rather than positional signatures for multi-variable utilities.
