## 2026-05-30 - Admin Login Rate Limit Bypass and IP Spoofing Risk
**Vulnerability:** The `/admin/login` and `/admin/login/2fa` endpoints called `guardRate` with incorrect parameters: `guardRate(c, "admin-login:" + ip, 5, 600)`, where `guardRate` expects `(c, scope, id, max, windowSec)`. This caused `windowSec` to be `undefined`, which resulted in `NaN` rolling window calculation, bypassing the configured 5/8 attempts limit up to 600 attempts, and then permanently blocking the IP once it hit 600. Additionally, client IP detection retrieved `x-forwarded-for` directly without defensive fallback/prioritization of Cloudflare-specific `cf-connecting-ip` header, leaving the rate-limiting keys vulnerable to IP spoofing.
**Learning:** Argument ordering mismatches in dynamically/loosely typed helper functions like `guardRate` can lead to silent authentication-bypass vulnerabilities and DoS. Directly parsing `x-forwarded-for` without verifying if the platform is deployed behind Cloudflare leaves the IP-attribution security context vulnerable to header injection.
**Prevention:** 1) Centralize IP resolution in a single defensive helper `getClientIP(c)` that checks for Cloudflare headers first and ensures `c.req.header` is a function before accessing it. 2) Rigorously enforce and type-check rate-limiting guard calls, using static analysis/unit tests to catch argument mismatches.
